// =========================================================== Description
== Description

// tag::body[]
{manpurpose}

Contrary to i3, `focus` command doesn't have a separate argument to focus floating windows.
From `focus` command perspective, floating windows are part of xref:guide.adoc#tree[the tree].
The floating window parent container is determined as the smallest tiling container that contains the center of the floating window.
The technique eliminates the need for an additional binding for floating windows.
This behavior can be disabled with `--ignore-floating` flag.

`focus container-next|container-prev` cycles within the nearest ancestor that has more than one focusable child window.
If the direct parent container contains only one window, AeroSpace climbs upward until it finds a wider ancestor, including the workspace root if needed, and wraps within that ancestor.
This is useful for accordion groups and nested single-child containers.
Boundary flags like `--boundaries`, `--boundaries-action`, and `--wrap-around` are not supported for container-local cycling.

`focus container-mru-next|container-mru-prev` uses the same container boundary but cycles through a short-lived snapshot ordered by focus recency.
The snapshot is reused for up to 750 milliseconds, so repeated invocations can visit every window without the order changing after each focus update.
`container-mru-prev` starts with the least recently focused window when a new cycle begins.

// =========================================================== Options
include::util/conditional-options-header.adoc[]

-h, --help:: Print help

--boundaries <boundary>::
Defines focus boundaries. +
`<boundary>` possible values: `(workspace|all-monitors-outer-frame)`. +
The default is: `workspace`

--boundaries-action <action>::
Defines the behavior when requested to cross the `<boundary>`. +
`<action>` possible values: `(stop|fail|wrap-around-the-workspace|wrap-around-all-monitors)`. +
The default is: `stop`

--wrap-around::
An alias for `--boundaries-action wrap-around-the-workspace`.
The flag is incompatible with either `--boundaries-action` or `--boundaries`.

--window-id <window-id>::
Focus the window with specified `<window-id>`

--dfs-index <dfs-index>::
Focus window by its index, based on a depth-first search (DFS) of the window within the workspace tree.
Index is 0-based.

--ignore-floating::
Don't perceive floating windows as part of the tree.
It may be useful for more reliable scripting.

--fail-if-fullscreen::
Exit with non-zero code if the current target window is fullscreen by the `fullscreen` command.
Only compatible with `(left|down|up|right)`.

--fail-if-macos-native-fullscreen::
Exit with non-zero code if the current target window is in macOS native fullscreen.
Only compatible with `(left|down|up|right)`.

// =========================================================== Arguments
include::./util/conditional-arguments-header.adoc[]

(left|down|up|right)::
Set focus to the nearest window in the given direction.

(dfs-next|dfs-prev)::
Set focus to the window before or after the current window in the depth-first order (top-to-bottom and left-to-right) of windows in the current workspace tree.
In this mode, `--boundaries` must be `workspace` (the default) and `--boundaries-action` can be set to one of `(stop|fail|wrap-around-the-workspace)`.

(container-next|container-prev)::
Set focus to the next or previous window inside the nearest ancestor that can actually cycle.
If the focused window lives inside a single-window container, the command walks upward until it finds a wider ancestor, including the workspace root if needed.
The command wraps within that ancestor and accepts `--ignore-floating`.

(container-mru-next|container-mru-prev)::
Set focus using a focus-recency snapshot inside the nearest ancestor that can actually cycle.
Repeated invocations reuse the snapshot for up to 750 milliseconds and wrap within it.
An external focus change, a different ancestor, or a changed window set starts a new cycle.
The command accepts `--ignore-floating`.
